## 仿真编排

### runAndPlot.py（621 行）

**职责**：串联网络生成→LEMS 仿真→结果绘图的完整流程。

**核心函数**：
- `run_c302(config, parameter_set, ...)` — 编排主函数

**问题**：
- `__main__` 块包含大量 CLI 快捷参数（`-fullC1`、`-oscB` 等），硬编码了配置×参数集的组合，约 200 行
- 配置模块通过字符串拼接加载：`"c302.c302_%s" % config`，与配置脚本命名紧耦合

### c302_utils.py（897 行）

**职责**：仿真结果可视化工具集。

**核心函数**：
- `plots()` — 热图绘制
- `generate_traces_plot()` — 轨迹叠加图
- `plot_c302_results()` — 主绘图函数（~290 行）
- `generate_conn_matrix()` — 连接矩阵可视化

**问题**：
- `plot_c302_results()` 函数过长（~290 行），混合了数据提取和绘图逻辑
- 文件名 `c302_utils` 过于笼统，实际全部是可视化函数

## 网络拓扑可视化

**职责**：解析 NeuroML XML → Graphviz DOT → PNG。

**问题**：

## 辅助工具

### CompareMain.py（361 行）

**职责**：比较两个连接组数据源的差异。

**问题**：
- 仅支持 XLS 格式（通过 `xlrd`），无法比较 CSV 或 cect 读取器
- 独立脚本，与主数据读取层无交互

### analyse.py（43 行）

**职责**：简易电压轨迹绘图。

**问题**：
- 🔴 **使用 Python 2 语法**：`volts.has_key(i)` 在 Python 3 中会抛出 `AttributeError`
- 纯脚本结构，无函数定义
- 功能与 `c302_utils.py` 的 `generate_traces_plot()` 重叠

### NeuroMLUtilities.py（86 行）

**职责**：3D 几何插值（从 NeuroML 形态中提取位置）。

**问题**：
- 导入了 `ConnectomeReader.analyse_connections` 但从未调用（死代码）
- 函数 `get3DPosition()` 与 `__init__.py::get_cell_position()` 功能重叠

### c302_info.py（156 行）

**职责**：输出包信息（版本、依赖、路径等）。

**问题**：无显著问题，但独立性高，可归入工具子包。

### backers.py（88 行）

**职责**：输出项目致谢名单。

**问题**：纯数据文件，不应占用模块命名空间。

```python
        "ParameterisedModel"
    )
    params = ParameterisedModel()

    cells_to_stimulate = [...]
    if generate:
        nml_doc = c302.generate(reference, params, cells=cells, ...)
    return cells, cells_to_stimulate, params, muscles_to_include, nml_doc
```

**分析**：
- ✅ 接口一致（`setup()` 返回 5 元组）
- ✅ 动态参数加载（`importlib`）
- 🟡 部分配置脚本在 `setup()` 后对 NML 文档做后处理（添加额外刺激、修改连接），这些逻辑散落各处
- 🟡 文件名 `c302_TapWithdrawal.py` 等使用 CamelCase，与 PEP 8 的 snake_case 不一致

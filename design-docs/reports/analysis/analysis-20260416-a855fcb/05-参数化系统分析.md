## 代码膨胀分析

### 🔴 parameters_C2.py — 1,956 行

这是所有参数文件中最大的，接近 `__init__.py` 的行数。膨胀原因：

1. **大量细胞特异参数**：为单个神经元设置独特的通道电导和时间常数
2. **硬编码参数列表**：每个参数通过 `self.add_bioparameter()` 调用逐一设置
3. **无数据驱动方式**：如果改用 YAML/JSON 数据文件，代码行数可降至 ~100 行

### 🟡 C0/C1 与 C 的关系

`parameters_C0.py`（711 行）和 `parameters_C1.py`（319 行）大量复制 `parameters_C.py`（628 行）的基础参数设置代码，仅修改少量参数值。更优做法是继承 C 的参数并覆盖差异项。

### 参数定义模式

所有参数集使用相同的注册模式：

```python
class ParameterisedModel(c302.bioparameters.c302ModelPrototype):
    def __init__(self):
        self.level = "C2"
        self.custom_component_types_definitions = [...]
        self.set_default_bioparameters()
    
    def set_default_bioparameters(self):
        self.add_bioparameter("param_name", "value", "Source", "0.1")
        self.add_bioparameter(...)  # 重复 N 次
    
    def create_neuron_to_neuron_syn(self):
        ...
    def create_neuron_to_muscle_syn(self):
        ...
    def create_models(self):
        ...
```

## 动态加载机制

配置脚本通过 `importlib` 动态加载参数集：

```python
ParameterisedModel = getattr(
    importlib.import_module("c302.parameters_%s" % parameter_set),
    "ParameterisedModel"
)
```

**优点**：运行时可切换，无需硬编码全部 10 个导入。
**缺点**：依赖文件命名约定 `parameters_{level}.py`，无注册表发现机制。

## 重构机会

1. **数据驱动参数定义**：将 `add_bioparameter()` 调用序列替换为 YAML/JSON 参数文件 + 加载函数
2. **参数继承优化**：C0/C1 继承 C 并仅覆盖差异参数，而非完整复制
3. **注册表模式**：提供 `list_available_parameter_sets()` 发现接口
4. **XML 组件文件关联**：`custom_component_types_definitions` 路径目前硬编码，应集中管理

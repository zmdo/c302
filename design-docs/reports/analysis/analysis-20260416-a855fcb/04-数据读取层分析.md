## 接口一致性

所有读取器遵循相同的鸭子类型接口：

```python
def read_data(include_nonconnected_cells=False):
    """返回 (cells: list[str], conns: list[ConnectionInfo])"""
    ...

def read_muscle_data():
    """返回 (neurons2muscles: dict, muscles: list[str], muscle_conns: list[ConnectionInfo])"""
    ...
```

**问题**：接口仅靠约定（鸭子类型），无抽象基类（ABC）强制。新增读取器时无编译期检查，容易遗漏方法。

## 代码重复分析

### 🔴 严重重复：UpdatedSpreadsheetDataReader 与 UpdatedSpreadsheetDataReader2

两个文件 271 行 vs 276 行，差异仅在：

| 差异点 | USDR1 | USDR2 |
|--------|-------|-------|
| 数据文件 | `herm_full_edgelist.csv` | `herm_full_edgelist_MODIFIED.csv` |
| 肌肉过滤 | 宽松（pre 或 post 为肌肉即可） | 严格（pre=neuron AND post=body_wall_muscle） |

以下函数完全相同（逐行一致）：

- `get_all_muscle_prefixes()`
- `get_body_wall_muscle_prefixes()`
- `is_muscle()`
- `is_body_wall_muscle()`
- `is_neuron()`
- `remove_leading_index_zero()`
- `get_old_muscle_name()`
- `get_syntype()`
- `get_synclass()`
- `parse_row()`

**估计重复率**：~90%（约 250 行中 225 行相同）

### 🟡 中度重复：White_whole / White_A / White_L4

三个文件各 38 行，结构完全相同，仅导入的 `cect.WhiteDataReader` 子类不同：

```python
# White_whole.py
from cect.WhiteDataReader import White_whole as WDR
read_data = WDR.read_data
read_muscle_data = WDR.read_muscle_data

# White_A.py
from cect.WhiteDataReader import White_A as WDR
# ... 完全相同的包装代码
```

**可合并为**：单一 `white_reader.py` + 工厂函数/字典注册表。

### ConnectomeReader.py 的角色特殊性

`ConnectomeReader.py`（733 行）并非真正的"读取器"——它不实现 `read_data()`，而是：
1. 定义了 302 个神经元名称常量
2. 定义了 96 个肌肉名称常量
3. 定义了 `ConnectionInfo` 数据类
4. 提供了 `analyse_connections()` 等分析函数

实际上它是整个数据层的**基础模块**，应更名或移至基础位置。

## 动态加载机制

`__init__.py::load_data_reader()` 通过 `importlib.import_module()` 加载读取器：

```python
def load_data_reader(data_reader):
    return importlib.import_module("c302.%s" % data_reader)
```

**调用约定**：`data_reader` 参数是模块名字符串，如 `"SpreadsheetDataReader"`。

**问题**：
1. 无注册表——新增读取器时必须知道确切模块名
2. 无验证——加载后不检查模块是否实现了必需接口
3. 无发现——用户无法列出可用读取器

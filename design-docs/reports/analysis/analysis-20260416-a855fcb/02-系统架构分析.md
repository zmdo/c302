## 物理结构 vs 逻辑架构——不匹配分析

| 逻辑层 | 应有的物理组织 | 实际状态 | 问题 |
|--------|--------------|----------|------|
| 数据读取层 | `c302/readers/` 子包 | 8 个文件散落在 `c302/` 根 | 与其他层混杂，无法一眼识别 |
| 参数化层 | `c302/parameters/` 子包 | 11 个文件散落在 `c302/` 根 | 文件名前缀 `parameters_` 是唯一分类手段 |
| 核心引擎层 | `c302/core/` 或拆分模块 | 全部塞在 `__init__.py`（2195 行） | 巨型文件，无法独立测试各步骤 |
| 配置脚本层 | `c302/configs/` 子包 | 16 个文件散落在 `c302/` 根 | 前缀 `c302_` 是唯一分类手段 |
| 仿真与可视化 | `c302/simulation/` 子包 | 3 个文件散落在 `c302/` 根 | 与工具混杂 |
| 辅助工具 | `c302/tools/` 子包 | 5 个文件散落在 `c302/` 根 | 职责不清 |
| XML 资源 | `c302/resources/` 子目录 | 7 个 XML 文件散落在 `c302/` 根 | 资源与代码混合 |

## 设计模式

| 模式 | 位置 | 评价 |
|------|------|------|
| **工厂** | `load_data_reader()` 动态加载读取器模块 | ✅ 好，但缺乏注册表 |
| **策略** | `importlib` 动态加载参数集 | ✅ 好，运行时可切换 |
| **模板方法** | `c302ModelPrototype` 定义 `create_*()` 抽象方法 | ✅ 好 |
| **适配器** | `White_*.py` 包装 `cect.WhiteDataReader` | 🟡 过度——3 个文件各 38 行 |
| **外观** | `runAndPlot.run_c302()` 编排全流程 | ✅ 好 |
| **上帝对象** | `__init__.py::generate()` 承担 13 个步骤 | 🔴 坏——应拆分为子模块 |

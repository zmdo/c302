# 05 - 遗留问题与建议

## P0：factory.py — 新的 God Object

### 问题描述

`parameters/factory.py`（1,877 行）是重构后最大的单文件，包含 11 个工厂类和 72 个方法。虽然已通过类继承消除了原始 10 个 `parameters_*.py` 文件间的**文件级重复**，但**方法级重复**仍然严重。

### 重复量化

| 方法名 | 重复次数 | 各实现差异程度 |
|--------|----------|----------------|
| `create_neuron_to_neuron_syn()` | 9 | 低（仅参数和组件类型不同） |
| `get_exc_syn_component_id()` | 7 | 极低（返回字符串不同） |
| `get_inh_syn_component_id()` | 7 | 极低（返回字符串不同） |
| `create_neuron_to_neuron_elec_syn()` | 6 | 低 |
| `create_models()` | 6 | 中（逻辑分支不同） |
| `create_n_to_m_conn()` | 4 | 低 |
| `create_inputs()` | 3 | 低 |

**估算：** 72 个方法中约 42 个是重复定义（58%），可通过参数化模板消除约 600-800 行代码。

### 建议

**拆分为 3-4 个文件（按模型族）：**

```
parameters/
├── factory/
│   ├── __init__.py     # create_model() + _LEVEL_TO_CLASS
│   ├── iaf.py          # _ModelBase, _IafModel, _IafActivityModel, _BC1Model
│   ├── hh.py           # _HHModel, _HHC0Model, _HHC1Model
│   ├── hh_multi.py     # _HHMultiCompModel, _HHGradedModel
│   └── special.py      # _C2Model, _W2DModel
```

**提取共享方法为 mixin 或基类方法：**

```python
# 将 create_neuron_to_neuron_syn 提升为 _ModelBase 方法
class _ModelBase:
    _syn_component_id: str  # 子类设置
    _exc_syn_id: str
    _inh_syn_id: str

    def create_neuron_to_neuron_syn(self, ...):
        # 使用 self._syn_component_id 等属性
        ...

    def get_exc_syn_component_id(self):
        return self._exc_syn_id
```

## P1：generate() 接口过于复杂

### 问题描述

`generator/__init__.py` 中的 `generate()` 函数接受 15+ 个参数：

```python
def generate(
    net_id, params, cells=None, cells_to_plot=None, cells_to_stimulate=None,
    conn_polarity=None, conn_number=None, duration=500, dt=0.05,
    vmin=-80, vmax=-40, ...
):
```

调用者需要记忆大量参数名和默认值，容易出错。

### 建议

引入配置对象：

```python
@dataclass
class GenerateConfig:
    net_id: str
    params: c302ModelPrototype
    duration: float = 500
    dt: float = 0.05
    vmin: float = -80
    vmax: float = -40
    cells: list[str] | None = None
    cells_to_plot: list[str] | None = None
    cells_to_stimulate: list[str] | None = None
    ...
```

## P2：字符串匹配的脆弱性

### 问题描述

参数查找依赖字符串匹配：

```python
# factory.py 中
def get_bioparameter(self, name):
    for bp in self.bioparameters:
        if bp.name == name:
            return bp
```

细胞分类同样基于字符串前缀：

```python
if cell.startswith("DD") or cell.startswith("VD"):
    cell_type = "inhibitory"
```

这种模式没有编译期检查，拼写错误只能在运行时暴露（且可能静默失败）。

### 建议

- 参数名使用 `enum` 或常量类
- 细胞分类使用查找表（dict）+ 类型校验

## P3：xfail 标记粒度过粗

### 问题描述

当前对 Muscles/Oscillator 的 xfail 标记在 config 级别：

```python
_KNOWN_CONFIG_DIFFS_CONFIGS = {"Muscles", "Oscillator"}
```

但实际上只有 `test_values_match` 会失败（参数覆盖顺序差异），而 `test_populations_match` 和 `test_connections_match` 是通过的。这导致 162 个 xpassed（意外通过），测试输出噪声大。

### 建议

将 xfail 粒度细化到 test 级别：

```python
@pytest.mark.parametrize("config,level", ALL_BASELINES)
def test_values_match(config, level):
    if config in _KNOWN_CONFIG_DIFFS_CONFIGS:
        pytest.xfail("Known parameter merge order difference")
    ...
```

## P4：configs 自动发现

### 问题描述

`configs/__init__.py` 中的 `_auto_import()` 硬编码了 16 个模块名：

```python
_modules = [
    "c302.configs.full",
    "c302.configs.fw",
    "c302.configs.iclamp",
    ...
]
```

新增配置需同时修改此列表，违反了开闭原则。

### 建议

改为自动扫描 `configs/` 目录下所有 `.py` 文件并导入。

## P5：仿真层测试覆盖不足

### 问题描述

`simulation/runner.py` 覆盖率仅 84%，主要缺口在实际调用外部仿真后端的分支。当前测试使用 mock，无法覆盖真实 jNeuroML/NEURON 执行路径。

### 建议

- 添加可选的集成测试 mark（`@pytest.mark.integration`），在 CI 中按需开启
- 对外部后端接口添加 contract test

## 总结

当前重构在宏观架构层面完成度很高，主要遗留问题集中在 `factory.py` 的微观重构上。P0 问题解决后，代码总行数可再减少 600-800 行，最大文件规模可控制在 400 行以内，模块评分将从 B+ 提升到 A−。

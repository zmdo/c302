# 05 - 遗留问题与建议

## 代码复审发现的 Bug

### Bug 1：`_C2Model.get_exc_syn` 变量未初始化（已修复）

**文件**：`parameters/factory/special.py` L397

**问题**：`get_exc_syn()` 在 `muscle_to_neuron` 分支中不赋值 `delta` 和 `k`，但末尾 `return GradedSynapse(... delta=delta, ... k=k)` 会触发 `UnboundLocalError`。

**严重程度**：低。`muscle_to_neuron` 路径在当前所有配置中均会命中 `cath` 或 `ar+ad+beta` 条件提前返回 `NeuronMuscle` / `GradedSynapse2`，不会走到最后的 `GradedSynapse` 分支。但代码逻辑上是一个真实的潜在崩溃点。

**修复**：在初始化行添加 `delta = k = None`，与 `cath`、`ar`、`ad`、`beta`、`vth`、`erev` 保持一致。

**来源**：此 bug 从原始 `parameters_C2.py` 继承而来，重构过程中未引入。

### Bug 2：`test_graded_synapse2_count` 空断言（已修复）

**文件**：`tests/test_equivalence.py` L320-333

**问题**：测试读取基线中的 `graded_synapses2` 期望值后，仅执行 `assert expected >= 0`（恒真），从未实际统计生成文档中的 GradedSynapse2 实例数量。该测试本质上是一个空操作。

**严重程度**：中。虽然当前所有基线的 `graded_synapses2` 均为 0（GradedSynapse2 与 GradedSynapse 共享 `nml_doc.graded_synapses` 列表），但测试失去了未来回归检测能力。

**修复**：改为使用 `isinstance(s, GradedSynapse2)` 从 `nml_doc.graded_synapses` 中计数，与基线值做精确比较。

## 非 Bug 的次要观察

### 1. `factory/__init__.py` — `_LEVEL_TO_CLASS` 每次调用重建

`create_model()` 每次调用都重新构建 `_LEVEL_TO_CLASS` 字典。可提升为模块级常量，但性能影响极小（仅在网络生成时调用一次）。

### 2. `factory/base.py` — 参数名 `type` 遮蔽内置函数

`get_exc_syn(self, pre_cell, post_cell, type)` 的 `type` 参数遮蔽了 Python 内置 `type()`。这是从原始代码继承的命名，修改会波及整个调用链。风险低，可在后续统一重命名。

### 3. `configs/__init__.py` — `_auto_import()` 无幂等保护

每次调用 `get_config()` 都会执行 `_auto_import()`，其中 `importlib.import_module()` 对已导入模块是幂等的（Python 缓存），但扫描文件系统有微小开销。可加 `_imported` 哨兵标志优化。

### 4. `configs/__init__.py` — `except ImportError: pass` 静默吞没错误

`_auto_import()` 中 `except ImportError: pass` 可能隐藏真实的导入错误。建议改为 `logging.debug()` 记录。

## 下一步建议

1. **参数名 `type` → `conn_type`**：全局重命名以避免遮蔽内置函数
2. **`_auto_import()` 加哨兵 + 日志**：防止重复扫描 + 记录导入失败
3. **`special.py`（636 行）进一步拆分**：`_HHC0Model`、`_C2Model`、`_W2DModel` 三个类无继承关系，可各自独立文件
4. **基线更新**：当 GradedSynapse2 在某些 config 中被实际使用时，更新 `graded_synapses2` 基线值使测试生效

# 05 - 可扩展性改进

## 问题概述

当前架构在新增参数层级、配置脚本、数据读取器等场景下，需要在多个文件中进行手动注册和样板代码编写。以下分析各扩展路径的摩擦点和改进方案。

---

## 扩展路径 #1：新增参数层级

### 当前步骤（5 步，涉及 3 文件）

以新增层级 `E` 为例：

1. **创建工厂文件** `factory/e.py`
   - 定义 `ParameterSetE` 类
   - 实现 `_init_bioparameters()`
   - 实现 `get_exc_syn()`、`get_inh_syn()`、`get_elec_syn()`（如果不同于父类）
   - 实现 `get_cell()` 等

2. **注册到工厂** `factory/__init__.py`
   - 添加 `from .e import ParameterSetE`
   - 在 `_LEVEL_MAP` 或 `get_parameter_set()` 中添加 `"E": ParameterSetE`

3. **添加测试基线** `tests/baselines/` 下生成 66 个基线文件

4. **添加测试用例** `tests/test_equivalence.py` 中追加 `"E"` 到层级列表

5. **更新文档** README.md、usage.md、development.md

### 摩擦点

- 步骤 2 是手动注册，容易遗漏
- 如果新层级的突触方法与父类相同，仍需要检查是否需要 override
- 缺少脚手架工具自动生成骨架

### 改进方案

**a) 自动发现注册：**

```python
# factory/__init__.py
import importlib, pkgutil

def _auto_discover():
    """自动发现 factory/ 下所有 ParameterSet* 子类。"""
    for _, name, _ in pkgutil.iter_modules(__path__):
        importlib.import_module(f".{name}", __package__)
```

类似于 `configs/` 已有的 `_auto_import` 机制。这样新增层级只需创建文件并继承基类，无需修改 `__init__.py`。

**b) 脚手架脚本：**

```bash
python -m c302.scaffold level E --parent D
# → 自动生成 factory/e.py 骨架
# → 自动注册（如采用自动发现则无需）
# → 打印后续步骤提示
```

## 扩展路径 #2：新增配置脚本

### 当前步骤（3 步，涉及 1 文件）

1. **创建配置文件** `configs/my_config.py`
   - 编写完整的 `setup()` 函数（~50–100 行）
   - 添加 `@register_config("MyConfig")` 装饰器
   - 配置会被 `_auto_import` 自动发现

2. **添加测试** `tests/test_equivalence.py` 中追加配置名

3. **生成基线** 运行测试生成 baseline 文件

### 摩擦点

- 每个配置需要编写完整的 `setup()` 函数，包括大量与其他配置相同的样板代码（签名、初始化、generate 调用）
- 配置之间的差异通常仅在于：选择哪些细胞、设置哪些参数覆盖、定义哪些刺激
- 缺少配置继承或组合机制

### 改进方案

**a) 声明式配置（长期）：**

将配置从过程式 Python 转为声明式数据结构：

```python
@register_config("MyNewConfig", default_duration=1000)
class MyNewConfig:
    cells = ["ADAL", "ADAR", "AVAL", "AVAR"]
    stimulate = ["ADAL", "ADAR"]
    offset_current = ("5 pA", "50 ms", "900 ms")
    param_overrides = {
        "neuron_to_neuron_exc_syn_conductance": "0.5 nS",
    }
```

框架负责签名包装、初始化、generate 调用。

**b) 配置组合（中期）：**

```python
@register_config("MyNewConfig")
def setup(parameter_set, **kwargs):
    return compose(
        base_setup(parameter_set, **kwargs),
        with_cells(["ADAL", "ADAR"]),
        with_offset_current("5 pA", "50 ms", "900 ms"),
    )
```

## 扩展路径 #3：新增数据读取器

### 当前步骤（2 步）

1. 创建读取器模块，实现 `read_data()` / `read_muscle_data()` 接口
2. 在调用处通过 `data_reader="新读取器"` 参数引用

### 摩擦点

- 缺少抽象基类或协议定义读取器接口
- 7 个读取器（SpreadsheetDataReader、UpdatedSpreadsheetDataReader、UpdatedSpreadsheetDataReader2、OpenWormReader、White_A、White_L4、White_whole）的接口约定隐式存在
- 读取器选择通过字符串名映射，映射关系在 `generator/__init__.py` 中硬编码

### 改进方案

**a) 读取器协议：**

```python
class DataReaderProtocol(Protocol):
    """数据读取器接口。"""
    def read_data(self, include_nonconnected: bool = False) -> ConnectomeData: ...
    def read_muscle_data(self) -> MuscleData: ...
```

**b) 读取器注册表：**

类似 `register_config` 模式：

```python
@register_reader("OpenWormReader")
class OpenWormReader:
    ...
```

替代 `generator/__init__.py` 中的硬编码映射。

## 扩展路径 #4：新增 NeuroML 自定义类型

### 当前步骤

1. 在 `custom_types.py` 中定义新类（继承已有 NeuroML 类型）
2. 在需要的工厂类中 import 并使用
3. 如果涉及 XML 组件定义，同步更新 `.xml` 文件

### 摩擦点

- `custom_types.py` 已有 11 个类（323 行），持续增长时可能需要拆分
- Python 类与 XML 定义的同步是手动的，容易不一致
- 新类型的参数字段需要在工厂方法中手动映射

### 改进方案

- 监控 `custom_types.py` 文件长度，超过 500 行时按突触类型/细胞类型拆分
- 考虑将参数字段映射声明为类属性而非工厂方法中的硬编码列表

---

## 总结：扩展摩擦点矩阵

| 扩展场景 | 当前步骤 | 需改文件数 | 主要摩擦点 | 建议优先级 |
|---------|------:|------:|---------|---------|
| 新增层级 | 5 | 3+ | 手动注册、无脚手架 | P2 |
| 新增配置 | 3 | 1 | 样板代码多 | P2 |
| 新增读取器 | 2 | 2 | 隐式接口 | P3 |
| 新增类型 | 3 | 2+ | 手动同步 | P3 |

# 02 - 硬编码字符串

## 问题概述

项目中存在大量硬编码的字符串字面值散布在多个文件中。这些字符串在语义上属于有限的枚举值或可推导的模板，但目前以裸字符串形式重复出现，增加了拼写错误风险和维护成本。

---

## 问题 #1：连接类型字符串（128+ 处）

### 现状

`"neuron_to_neuron"`、`"neuron_to_muscle"`、`"muscle_to_muscle"`、`"muscle_to_neuron"` 四个字符串作为 `conn_type` 参数值，在以下位置反复出现：

| 文件 | 出现次数 | 典型用法 |
|------|------:|---------|
| `factory/base.py` | 9 | `if conn_type == "neuron_to_neuron":` |
| `factory/c2.py` | 9 | `if conn_type == "neuron_to_neuron":` |
| `factory/w2d.py` | 3 | `if conn_type == "neuron_to_neuron":` |
| `generator/connection.py` | 3 | `get_syn(pre, post, "neuron_to_neuron", pol)` |
| `parameters/model.py` | 3 | `get_elec_syn(pre, post, conn_type)` 的 conn_type 传递 |

此外，`generator/connection.py` 中的调用者通过裸字符串传入：

```python
# connection.py L479
syn = params.get_syn(pre_pop, post_pop, "neuron_to_neuron", polarity)
# connection.py L537
syn = params.get_syn(pre_pop, post_pop, "neuron_to_muscle", polarity)
```

### 风险

- 拼写错误不会被 IDE 或类型检查器捕获（如 `"neruon_to_neuron"`）
- 重命名需要全局搜索替换，容易遗漏

### 建议方案

在 `parameters/` 下新建 `constants.py`（或直接放在 `model.py` 中）：

```python
class ConnType:
    """连接类型常量。"""
    NEURON_TO_NEURON = "neuron_to_neuron"
    NEURON_TO_MUSCLE = "neuron_to_muscle"
    MUSCLE_TO_MUSCLE = "muscle_to_muscle"
    MUSCLE_TO_NEURON = "muscle_to_neuron"
```

所有 `conn_type == "neuron_to_neuron"` 改为 `conn_type == ConnType.NEURON_TO_NEURON`。

## 问题 #2：突触参数名模板（80+ 处）

### 现状

突触参数名遵循固定模式 `"{conn_type}_{polarity}_syn_{field}"`，但目前在每个方法中手动拼接：

```python
# base.py — get_exc_syn 中
default = "neuron_to_neuron_exc_syn_%s"
conductance = self.get_conn_param(pre, post, specific, default, "conductance")
erev = self.get_conn_param(pre, post, specific, default, "erev")
# ... 每个字段重复调用
```

```python
# c2.py — get_elec_syn 中连续 9 次调用
gbase = self.get_conn_param(pre, post, "%s_to_%s_elec_syn_%s",
    "neuron_to_neuron_elec_syn_%s", "gbase")
sigma = self.get_conn_param(pre, post, "%s_to_%s_elec_syn_%s",
    "neuron_to_neuron_elec_syn_%s", "sigma")
mu = self.get_conn_param(pre, post, "%s_to_%s_elec_syn_%s",
    "neuron_to_neuron_elec_syn_%s", "mu")
# ... 6 more
```

### 风险

- 模板字符串 `"%s_to_%s_exc_syn_%s"` 重复 30+ 次
- 默认前缀 `"neuron_to_neuron_exc_syn_%s"` 可由 `conn_type` 推导但手动硬编码
- 新增参数字段时需要在多处添加调用

### 建议方案

1. 默认模板可由 `conn_type` 直接推导：

```python
# 当前（hardcoded）
if conn_type == "neuron_to_neuron":
    default = "neuron_to_neuron_exc_syn_%s"
elif conn_type == "neuron_to_muscle":
    default = "neuron_to_muscle_exc_syn_%s"

# 优化后
default = f"{conn_type}_exc_syn_%s"
```

2. 批量查询替代逐字段调用：

```python
# 当前（9 行重复调用）
gbase = self.get_conn_param(pre, post, spec, default, "gbase")
sigma = self.get_conn_param(pre, post, spec, default, "sigma")
# ... 7 more

# 优化后（2 行）
fields = ("gbase", "sigma", "mu", "p_gbase", "p_ar", "p_ad", "beta", "vth", "erev")
vals = {f: self.get_conn_param(pre, post, spec, default, f) for f in fields}
```

## 问题 #3：配置文件引用字符串（16 处）

### 现状

每个配置脚本手动构建引用名称：

```python
# full.py
reference = "c302_%s_Full" % parameter_set
# iclamp.py
reference = "c302_%s_IClamp" % parameter_set
# social.py
reference = "c302_%s_Social" % parameter_set
```

配置名已经在 `@register_config("Full")` 中声明。

### 建议方案

将 `reference` 构建移入 `register_config` 装饰器或公共辅助函数：

```python
def make_reference(config_name: str, parameter_set: str) -> str:
    return f"c302_{parameter_set}_{config_name}"
```

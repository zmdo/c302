# 04 - 配置脚本模板化

## 问题概述

16 个配置脚本（`configs/*.py`）共享高度相似的 `setup()` 函数骨架，但当前各自独立实现全部样板代码。

---

## 问题 #1：完全相同的函数签名（16 处）

### 现状

所有 16 个配置脚本的 `setup()` 函数签名完全一致：

```python
def setup(
    parameter_set,
    generate_flag=False,
    duration=...,           # 仅此处不同
    dt=0.05,
    target_directory="examples",
    data_reader=DEFAULT_DATA_READER,
    param_overrides=None,
    config_param_overrides=None,
    verbose=True,
):
```

9 个参数中仅 `duration` 的默认值不同（值域：500–2000）。

### 涉及文件

| 配置 | duration 默认值 | 文件 |
|------|----------:|------|

## 问题 #2：相同的初始化样板（16 × 3 行 = 48 行）

### 现状

每个 `setup()` 函数开头都是：

```python
if param_overrides is None:
    param_overrides = {}
params = get_parameter_set(parameter_set)
```

部分配置还额外添加：
```python
if config_param_overrides:
    process_bioparameters(params, config_param_overrides)
```

### 建议方案

引入 `setup_base()` 辅助函数：

```python
def setup_base(parameter_set, param_overrides, config_param_overrides):
    """配置脚本公共初始化。"""
    if param_overrides is None:
        param_overrides = {}
    params = get_parameter_set(parameter_set)
    if config_param_overrides:
        process_bioparameters(params, config_param_overrides)
    return params, param_overrides
```

## 问题 #3：`unphysiological_offset_current` 三元组（10 个配置，30 行）

### 现状

10 个配置中出现完全相同模式的三行设置：

```python
params.set_bioparameter(
    "unphysiological_offset_current", "5 pA",
    "KnsownGood", "Testing %s" % "Full")
params.set_bioparameter(
    "unphysiological_offset_current_del", "50 ms",
    "KnownGood", "Testing %s" % "Full")
params.set_bioparameter(
    "unphysiological_offset_current_dur", "900 ms",
    "KnownGood", "Testing %s" % "Full")
```

只有值和配置名不同。

### 建议方案

```python
def set_offset_current(params, current, delay, duration, config_name):
    """设置非生理偏置电流三元组。"""
    for suffix, value in [("", current), ("_del", delay), ("_dur", duration)]:
        params.set_bioparameter(
            f"unphysiological_offset_current{suffix}", value,
            "KnownGood", f"Testing {config_name}",
        )
```

每个配置文件中从 3 行减少为 1 行调用。

## 问题 #4：`generate()` 调用模式（16 处）

### 现状

每个配置结尾都是：

```python
if generate_flag:
    nml_doc = generate(
        reference, params, cells=cells, cells_to_stimulate=cells_to_stimulate,
        conn_polarity=conn_polarity, muscles_to_include=muscles_to_include,
        duration=duration, dt=dt, target_directory=target_directory,
        param_overrides=param_overrides, verbose=verbose,
        data_reader=data_reader,
    )
```

参数列表几乎完全相同，差异仅在于部分配置传递了 `muscles_to_include` 或 `conn_polarity` 而其他不传。

### 建议方案

在 `@register_config` 装饰器或基类中提供默认的 `generate` 调用包装，配置脚本只需返回一个 `SetupResult` 数据对象：

```python
@dataclass
class SetupResult:
    reference: str
    params: ParameterSet
    cells: list
    cells_to_stimulate: list
    conn_polarity: dict | None = None
    muscles_to_include: list | None = None
```

装饰器负责调用 `generate()`，配置只需关注自身逻辑。

## 问题 #5：`reference` 字符串手动构建（16 处）

### 现状

```python
reference = "c302_%s_Full" % parameter_set       # full.py
reference = "c302_%s_IClamp" % parameter_set     # iclamp.py
reference = "c302_%s_Social" % parameter_set     # social.py
```

配置名已在 `@register_config("Full")` 中声明，无需重复。

### 建议方案

将 `reference` 构建逻辑移入 `register_config` 装饰器或 `setup_base()`：

```python
# register_config 注入 config_name，setup 中使用
reference = make_reference(config_name, parameter_set)
```

或在装饰器中直接传入 `config_name` 参数：

```python
@register_config("Full", default_duration=1000)
def setup(parameter_set, *, config_name, **kwargs):
    reference = make_reference(config_name, parameter_set)
```

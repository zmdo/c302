## 1. USDR1/USDR2 代码重复

**严重度**：🟡 中
**涉及文件**：`UpdatedSpreadsheetDataReader.py`（271 行）、`UpdatedSpreadsheetDataReader2.py`（276 行）

### 问题描述

两个文件的差异仅有 2 处：

1. **数据文件名**：`herm_full_edgelist.csv` vs `herm_full_edgelist_MODIFIED.csv`
2. **肌肉过滤逻辑**：USDR1 宽松（pre 或 post 为肌肉即可），USDR2 严格（pre=neuron AND post=body_wall_muscle）

以下 10 个函数逐行相同：
- `get_all_muscle_prefixes()`
- `get_body_wall_muscle_prefixes()`
- `is_muscle()`
- `is_body_wall_muscle()`
- `is_neuron()`
- `remove_leading_index_zero()`
- `get_old_muscle_name()`
- `get_syntype()`
- `get_synclass()`
- `parse_row()`

### 风险 / 为什么当前能正常工作

两个文件独立维护时，修复一个文件的 bug 需要记得同步修复另一个。目前因为文件很少被修改所以未出问题。

### 建议修复

合并为单一模块 `csv_reader.py`：

```python
# c302/readers/csv_reader.py

def read_data(include_nonconnected_cells=False,
              filename="herm_full_edgelist.csv",
              strict_muscle_filter=False):
    """统一 CSV 读取器。
    
    :param filename: CSV 数据文件名
    :param strict_muscle_filter: True=USDR2 的严格过滤模式
    """
    ...
```

旧模块保留为薄包装以兼容：

```python
# c302/readers/updated_spreadsheet.py (兼容层)
from c302.readers.csv_reader import read_data as _read_data

def read_data(include_nonconnected_cells=False):
    return _read_data(include_nonconnected_cells, filename="herm_full_edgelist.csv")
```

## 2. White 适配器重复

**严重度**：🟡 中
**涉及文件**：`White_whole.py`、`White_A.py`、`White_L4.py`（各 38 行）

### 问题描述

三个文件结构完全相同，仅导入的 `cect.WhiteDataReader` 子类不同：

```python
# White_whole.py 核心逻辑：
from cect.WhiteDataReader import White_whole as WDR
read_data = WDR.read_data
read_muscle_data = WDR.read_muscle_data
```

### 风险 / 为什么当前能正常工作

文件极简（38 行），维护成本低。但 3 个几乎相同的文件增加了认知负担。

### 建议修复

合并为单一 `white.py` + 工厂函数：

```python
# c302/readers/white.py

from cect import WhiteDataReader

_VARIANTS = {
    "whole": WhiteDataReader.White_whole,
    "A": WhiteDataReader.White_A,
    "L4": WhiteDataReader.White_L4,
}

def get_reader(variant="whole"):
    """获取 White et al. 数据读取器。"""
    return _VARIANTS[variant]
```

## 3. 缺乏抽象基类（ABC）

**严重度**：🟡 中
**涉及文件**：全部 `*Reader.py`

### 问题描述

所有读取器通过鸭子类型约定实现相同接口：

```python
def read_data(include_nonconnected_cells=False):
    ...
def read_muscle_data():
    ...
```

但无 ABC 定义。新增读取器时无法通过 IDE 或类型检查发现缺失方法。

### 风险 / 为什么当前能正常工作

读取器集合稳定（8 年来变化不大），新增读取器的需求不频繁。但没有形式化接口意味着：
- IDE 无法提供接口方法提示
- 类型检查工具无法验证接口完整性
- `load_data_reader()` 加载后无法验证模块是否符合接口

### 建议修复

在 `c302/readers/__init__.py` 中定义 ABC：

```python
from abc import ABC, abstractmethod

class BaseDataReader(ABC):
    """连接组数据读取器的抽象基类。"""
    
    @staticmethod
    @abstractmethod
    def read_data(include_nonconnected_cells=False):
        """读取连接组数据。
        
        :return: (cells: list[str], conns: list[ConnectionInfo])
        """
        ...
    
    @staticmethod
    @abstractmethod
    def read_muscle_data():
        """读取神经元-肌肉连接数据。
        
        :return: (neurons2muscles: dict, muscles: list[str], muscle_conns: list[ConnectionInfo])
        """
        ...
```

## 4. ConnectomeReader 角色定位不清

**严重度**：🟢 低
**涉及文件**：`ConnectomeReader.py`（733 行）

### 问题描述

`ConnectomeReader.py` 命名暗示它是一个"读取器"，但实际上它：
1. 不实现 `read_data()` / `read_muscle_data()` 接口
2. 定义 302 个神经元名称常量 + 96 个肌肉名称常量
3. 定义 `ConnectionInfo` 数据类
4. 提供 `analyse_connections()` 等分析辅助函数

它实际上是数据层的**基础模块**（常量 + 数据结构），不是读取器。

### 建议修复

重命名为 `connectome.py` 并放入 `c302/readers/` 子包，明确其"基础定义"角色。

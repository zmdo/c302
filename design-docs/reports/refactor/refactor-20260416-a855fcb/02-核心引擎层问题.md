## 1. `__init__.py` 巨型模块

**严重度**：🔴 高
**涉及文件**：`project/c302/__init__.py`（2195 行）

### 问题描述

`__init__.py` 是 c302 的核心模块，承担了以下 6 类完全不同的职责：

1. **CLI 入口**（`main()`、`process_args()`、`parse_list_arg()`、`parse_dict_arg()`）— 229 行
2. **网络生成**（`generate()`、`set_param()`、`mirror_param()`）— 1204 行
3. **刺激注入**（`add_new_input()`、`add_new_sinusoidal_input()`、`append_input_to_nml_input_list()`、`get_next_stim_id()`）— 101 行
4. **文件 I/O**（`write_to_file()`、`merge_with_template()`、`get_file_name_relative_to_c302()`）— 77 行
5. **数据桥接**（`load_data_reader()`、`get_cell_names_and_connection()`、`get_cell_muscle_names_and_connection()`、`_get_cell_info()`）— 167 行
6. **通用工具**（`print_()`、`get_str_from_exponential()`、`get_random_colour_hex()`、正则匹配、位置计算）— 148 行

将 6 类职责塞入一个文件违反了单一职责原则（SRP），导致：
- 单个文件修改频率极高（任何变更都可能触碰此文件）
- 无法对各职责进行独立单元测试
- 阅读和导航困难
- Git blame / diff 噪声大

### 风险 / 为什么当前能正常工作

当前能正常工作是因为 `generate()` 函数的控制流是线性的（步骤 1→13 顺序执行），不存在复杂的分支或并发。但随着功能扩展（如新增模型类型、新增读取器），修改 `__init__.py` 的冲突概率会线性增长。

### 建议修复

拆分为以下子模块结构：

```
c302/
├── __init__.py          # 瘦身：仅 re-export 公共 API + 常量
├── cli.py               # main(), process_args(), parse_*_arg()
├── core/
│   ├── __init__.py
│   ├── generator.py     # generate(), set_param(), mirror_param()
│   ├── stimulation.py   # add_new_input(), add_new_sinusoidal_input(), ...
│   ├── io.py            # write_to_file(), merge_with_template()
│   ├── positions.py     # get_muscle_position(), get_cell_position(), ...
│   ├── data_bridge.py   # load_data_reader(), get_cell_names_and_connection()
│   └── utils.py         # print_(), get_str_from_exponential(), regex helpers
```

**关键**：`c302/__init__.py` 必须 re-export 所有公共函数以保持向后兼容：

```python
# c302/__init__.py（重构后）
from c302.core.generator import generate
from c302.core.stimulation import add_new_input, add_new_sinusoidal_input
from c302.core.io import write_to_file
from c302.core.utils import print_
from c302.cli import main, process_args
# ... 等等
```

## 2. 扁平包结构

**严重度**：🔴 高
**涉及文件**：全部 `project/c302/*.py`（47 个文件）

### 问题描述

47 个 .py 文件平铺在 `c302/` 根目录：

```

├── bioparameters.py         # 参数基类

├── parameters_B.py          # │

├── parameters_C.py          # │
├── ...                      # ┘
├── ConnectomeReader.py      # ┐
├── SpreadsheetDataReader.py # │ 8 个读取器
├── ...                      # ┘
├── c302_Full.py             # ┐
├── c302_FW.py               # │ 15 个配置脚本

├── c302_utils.py            # ┐

└── *.xls(x) (2)             # 数据文件混入
```

用户/开发者看到这个目录时，无法快速理解文件间的关系和层次结构。

### 风险 / 为什么当前能正常工作

文件命名约定（`parameters_*`、`c302_*`、`*Reader`）提供了隐式分类，但这依赖开发者的先验知识。新开发者需要阅读文档才能理解哪些文件属于同一层。

## 1. parameters_C2.py 参数膨胀

**严重度**：🟡 中
**涉及文件**：`parameters_C2.py`（1956 行）

### 问题描述

`parameters_C2.py` 是仅次于 `__init__.py` 的第二大文件，几乎全部由 `self.add_bioparameter()` 调用构成：

```python
def set_default_bioparameters(self):
    self.add_bioparameter("neuron_to_neuron_elec_syn_gbase", "0.0005 nS", "BlindGuess", "0.1")
    self.add_bioparameter("ADAL-ADAR_GJ_sigma", "...", "...", "...")
    # ... 重复约 200 次
```

大量细胞特异参数（如 `ADAL-ADAR_GJ_sigma`）以代码形式硬编码，而这些参数本质上是数据。

### 风险 / 为什么当前能正常工作

功能上没有问题——Python 解释器忠实执行每一行。但 1956 行的"数据即代码"风格意味着：
- 参数调整需要编辑 Python 文件而非数据文件
- 难以进行批量参数搜索/替换
- 无法用表格工具（Excel/pandas）分析参数集

### 建议修复

**长期方案**（不在本次重构范围内）：将参数定义迁移到 YAML 文件：

```yaml
# c302/parameters/data/level_c2.yaml
neuron_to_neuron_elec_syn_gbase:
  value: "0.0005 nS"
  source: "BlindGuess"
  certainty: "0.1"
ADAL-ADAR_GJ_sigma:
  value: "..."
  source: "..."
  certainty: "..."
```

**本次重构**：仅移入子包 `c302/parameters/level_c2.py`，不改动参数定义方式。

## 2. C0/C1 参数代码复制

**严重度**：🟡 中
**涉及文件**：`parameters_C0.py`（711 行）、`parameters_C1.py`（319 行）、`parameters_C.py`（628 行）

### 问题描述

C0 和 C1 是 C 的变体，但各自独立复制了 C 的大部分基础参数定义代码。例如 C0 复制了 C 的全部基础参数然后修改了少量值（去掉 fast K 通道），而非继承 C 并仅覆盖差异。

### 风险 / 为什么当前能正常工作

参数集变更频率极低（科学参数一旦验证通过很少修改），所以代码重复的维护成本目前可控。

### 建议修复

**本次重构不改**——参数继承优化属于"持续改进"，修改风险较高（可能改变仿真结果），应在有完善测试覆盖后再进行。本次仅将文件移入 `c302/parameters/` 子包。

## 3. 配置脚本命名不一致

**严重度**：🟢 低
**涉及文件**：15 个 `c302_*.py` 文件

### 问题描述

配置脚本使用 CamelCase 命名（`c302_TapWithdrawal.py`、`c302_IClamp.py`），与 PEP 8 的 snake_case 模块命名规范不一致。

### 风险 / 为什么当前能正常工作

Python 对模块名大小写不敏感（macOS/Windows），Linux 上区分大小写但名称稳定。`runAndPlot.py` 通过字符串拼接 `"c302.c302_%s" % config` 加载，只要名称匹配即可。

### 建议修复

移入 `c302/configs/` 子包时统一为 snake_case（`tap_withdrawal.py`、`iclamp.py`）。在 `configs/__init__.py` 中提供名称映射表以兼容旧的字符串引用：

```python
# c302/configs/__init__.py
CONFIG_ALIASES = {
    "Full": "full",
    "FW": "fw",
    "IClamp": "iclamp",
    "TapWithdrawal": "tap_withdrawal",
    # ...
}
```

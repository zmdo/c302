## 实施原则

1. **渐进式重构**：每个阶段保持项目可运行，不在一次提交中大规模重组
2. **向后兼容**：重构后 `c302.generate()`、`c302.add_new_input()` 等公共 API 保持可用
3. **先建测试后重构**：关键模块先建立基线测试，再进行结构变更
4. **先移后拆**：先将文件移入子包（低风险），再拆分巨型文件（高风险）
5. **逻辑零修改**：每步只做结构调整，不修改业务逻辑

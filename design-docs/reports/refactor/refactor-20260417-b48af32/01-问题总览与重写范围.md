## 保留的设计决策

重写不意味着推翻一切。以下原代码中的优良设计应在新代码中保留：

| 设计决策 | 原代码做法 | 保留理由 |
|----------|-----------|----------|
| 动态参数集加载 | `importlib.import_module()` | 灵活、运行时可切换，是正确的策略模式 |
| `BioParameter` 四元组 | `name/value/source/certainty` | 科学计算需要追踪参数来源和确信度 |
| 模板方法模式 | `c302ModelPrototype` 定义抽象方法，子类实现 | 清晰的继承层次 |
| 配置脚本 `setup()` 统一接口 | 所有配置返回 `(cells, cells_to_stimulate, params, muscles, nml_doc)` | 一致性好 |
| owmeta 可选依赖 | `try/except` 保护导入 | 正确的可选依赖处理 |
| 连接组数据统一接口 | `read_data()` + `read_muscle_data()` | 鸭子类型接口清晰（新代码将用 ABC 形式化） |

## 舍弃的设计决策

| 设计决策 | 原代码做法 | 舍弃理由 |
|----------|-----------|----------|
| 全部逻辑塞入 `__init__.py` | 2195 行巨型模块 | 违反 SRP，无法独立测试 |
| 参数硬编码在 Python 中 | `self.add_bioparameter()` × 200+ | 应数据驱动（YAML/JSON） |
| 文件名 CamelCase | `CompareMain.py`, `UpdatedSpreadsheetDataReader.py` | 违反 PEP 8，新代码全部 snake_case |
| 资源与代码混放 | XML/XLS 与 .py 同目录 | 新代码严格分离 |
| Shell 集成测试 | `test.sh` | 改用 pytest 框架 |
| `setup.py` 打包 | 传统 `setup()` 调用 | 改用 `pyproject.toml` |

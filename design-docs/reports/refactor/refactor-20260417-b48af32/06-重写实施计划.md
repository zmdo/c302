## 实施策略

**方法**：自底向上重写（bottom-up rewrite）

在 `project_r1/` 目录从零构建，按依赖顺序由底层到顶层逐模块重写。每完成一层模块即运行单元测试，保证该层正确后再推进上层。

**不采用**：渐进式重构（原代码耦合严重，逐步拆分成本高于重写）

## 风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| 参数 YAML 化时丢失参数 | 网络生成错误 | 自动化脚本提取 + 对比验证 |
| 原代码隐含行为未被文档覆盖 | 等价性测试失败 | 保留原代码作为参考，逐案修复 |
| cect/pyNeuroML API 变更 | 外部依赖不兼容 | 锁定依赖版本 |
| LEMS 模板合并逻辑复杂 | 仿真文件不正确 | 复制原模板，逐步验证 |
| 302 神经元名称有特殊规则 | 名称匹配失败 | 保留原始常量数据，不做修改 |

# 01 - 概述与目标

## 背景

c302 是 OpenWorm 项目的子模块，用于生成秀丽隐杆线虫 302 个神经元的多尺度 NeuroML 2 网络模型。项目历时 8 年、550+ 次提交，功能稳定可用，但代码组织存在以下结构性问题：

1. **扁平包结构**：47 个 Python 文件（16,260 行）平铺在 `c302/` 单一目录下，无子包划分
2. **巨型核心模块**：`__init__.py` 承载 2195 行、32 个函数、6 类不同职责（CLI / 生成 / I/O / 刺激 / 数据桥接 / 工具）
3. **代码重复**：`UpdatedSpreadsheetDataReader.py` 与 `UpdatedSpreadsheetDataReader2.py` 重复率 ~90%；`White_*.py` 三个文件模式相同
4. **无单元测试**：仅有 `test.sh` 集成测试，无 pytest 框架
5. **工程化缺失**：隐式依赖未声明、资源文件与代码混放、传统 `setup.py` 打包

详见代码分析报告 `analysis-20260416-a855fcb` 和重构建议报告 `refactor-20260416-a855fcb`。

## 目标

1. 将 47 个文件按四层逻辑架构重组为 7 个子包（`core/`、`readers/`、`parameters/`、`configs/`、`visualization/`、`simulation/`、`tools/`）+ `resources/` 资源目录
2. 将 `__init__.py` 的 32 个函数拆分为 6 个子模块（`generator.py`、`stimulation.py`、`io.py`、`positions.py`、`data_bridge.py`、`utils.py`）+ 1 个 CLI 模块
3. 消除数据读取层的代码重复（合并 USDR1/2、合并 White 适配器）
4. 引入 `BaseDataReader` ABC 定义标准接口
5. 建立 pytest 单元测试框架，覆盖拆分后的核心模块
6. 修复已知缺陷（`analyse.py` Python 2 语法、死代码导入、依赖缺失）
7. 全程保持向后兼容——旧导入路径通过兼容层继续可用

## 不做什么

- 不修改任何仿真逻辑或参数值（代码行为与重构前完全等价）
- 不将参数定义迁移到 YAML/JSON（属于后续优化，风险高）
- 不重构 C0/C1 的参数继承关系（需要仿真结果验证，超出本计划范围）
- 不修改 `data/`、`NeuroML2/` 目录结构（已合理组织）
- 不修改 GitHub Actions CI 工作流（保持现有集成测试）
- 不删除旧位置的兼容文件（保留至少一个版本周期）
- 不将 `setup.py` 迁移到 `pyproject.toml`（属于后续优化，与本次架构重组无关）
- 不修改 XML / LEMS / NeuroML 文件内容

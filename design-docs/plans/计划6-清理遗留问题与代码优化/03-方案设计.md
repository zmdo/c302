## 总体架构

计划 6 是纯重构，不改变任何公共 API 行为。变更范围限于：

```
parameters/factory/          configs/

├── base.py      ← type→conn_type
```

## 方案 1：`type` → `conn_type` 重命名

### 策略

- 在所有方法签名中将 `type` 参数重命名为 `conn_type`
- 同步修改方法体内所有 `type` 变量引用
- 影响范围：`base.py`、`special.py`（拆分后为 `c2.py` + `w2d.py`）、`model.py`
- `generator/connection.py` 不需修改（已使用 `conn_type` 变量名，通过位置参数传递）

### 风险评估

- 所有调用均为位置参数传递（`get_syn(pre, post, conn_type, pol)`），不存在关键字参数调用
- 等价性测试覆盖所有路径，重命名纯粹是形参名变更

## 方案 2：`_auto_import()` 优化

### 策略

```python
_imported = False  # 模块级哨兵

def _auto_import() -> None:
    global _imported
    if _imported:
        return
    _imported = True
    
    import importlib
    import pkgutil
    for finder, name, ispkg in pkgutil.iter_modules(__path__, __name__ + "."):
        try:
            importlib.import_module(name)
        except ImportError:
            logger.debug("配置模块 %s 导入失败", name, exc_info=True)
```

- 添加 `_imported` 哨兵防止重复扫描
- 将 `pass` 替换为 `logger.debug()`，保留错误诊断信息
- 需在文件顶部添加 `import logging` 和 `logger = logging.getLogger(__name__)`

## 方案 3：`special.py` 拆分

### 策略

将 `special.py` 拆分为 3 个文件：

| 原文件 | 新文件 | 内容 | 行数 |
|--------|--------|------|------|
| `special.py` L1-75 | `special.py`（保留） | 文件头 + 公共导入（若有） | ~10 |
| `special.py` L77-568 | `c2.py` | `_C2Model` | ~492 |
| `special.py` L570-639 | `w2d.py` | `_W2DModel` | ~70 |

拆分后 `special.py` 可删除（内容全部移至 `c2.py` + `w2d.py`）。

### 导入调整

`factory/__init__.py` 中的导入需更新：

```python
# 原
from c302.parameters.factory.special import _C2Model, _W2DModel
# 新
from c302.parameters.factory.c2 import _C2Model
from c302.parameters.factory.w2d import _W2DModel
```

```python
_LEVEL_TO_CLASS: dict[str, type] = {

def create_model(level: str) -> c302ModelPrototype:
    level_upper = level.upper()
    cls = _LEVEL_TO_CLASS.get(level_upper)

```

## 执行顺序

1. **先拆分 `special.py`**（结构性变更，影响后续步骤）
2. **再重命名 `type` → `conn_type`**（跨文件变更，拆分后文件更小、更易操作）
3. **优化 `_auto_import()`**（独立，不影响其他步骤）
4. **提升 `_LEVEL_TO_CLASS`**（独立，不影响其他步骤）
5. **更新文件头索引 + 全量回归测试**

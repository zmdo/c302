# 03 - 方案设计

## 总体架构

```
注释任务执行流程：

① 建立词汇表
   design-docs/glossary.md
   ─ 确立领域术语中英对照，所有注释人员统一使用
         │
         ▼
② 构建验证工具（前置）
   scripts/verify-comment-only/verify_comment_only.py
   ─ 先于注释工作完成，确保后续每次修改可验证
         │
         ▼
③ 按优先级逐层添加中文注释
   阶段一：数据读取层（P0）→ 阶段二：参数化层（P1）
   → 阶段三：网络生成层（P2）→ 阶段四：仿真/可视化（P3）
   → 阶段五：配置脚本层（P5）
         │
         ▼
④ 每文件修改后运行验证脚本
   verify_comment_only.py <原文件备份> <修改后文件>
   ─ Hash 相等 → 合格  |  Hash 不等 → 报错回滚
         │
         ▼
⑤ 提交
```

## 核心约束

**只增改注释，不动代码**是本计划的硬性约束。具体定义如下：

| 允许的操作 | 不允许的操作 |
|-----------|------------|
| 新增 `#` 行内注释行 | 修改任何语句或表达式 |
| 替换英文 `#` 注释为中文 `#` 注释 | 修改变量名、函数名、类名 |
| 在代码行末尾添加 `  # 中文说明` | 修改字符串字面量（即使只改注释用的字符串） |
| 删除英文注释并换成中文注释（同位置） | 删除任何非注释内容 |
| | 重新格式化代码（空格、缩进） |

## 验证工具设计

### 原理

通过 Python 标准库 `tokenize`（官方库，精确识别注释 token）去除注释，再通过 `ast.unparse(ast.parse(...))` 格式化，最后比较 SHA-256 哈希值：

```
原文件 ──tokenize去注释──► src_no_comm
                                        ──► format(src_no_comm) ──► Hash A
修改后 ──tokenize去注释──► t_src_no_comm
                                        ──► format(t_src_no_comm) ──► Hash B

Hash A == Hash B → 仅注释变更（通过）
Hash A != Hash B → 代码被改动（失败，报告差异）
```

### 关键设计决策

| 决策 | 选择 | 原因 |
|------|------|------|
| 注释去除方法 | `tokenize` 标准库 | 官方库，精确识别注释 token，不会误删字符串中的 `#` |
| 格式化方法 | `ast.unparse(ast.parse(src))` | 去除所有空白差异，确保纯注释行增删不影响比较 |
| 哈希算法 | SHA-256 | 标准库 `hashlib`，无依赖 |
| 对比粒度 | 文件级 | 简单直接，适合 CI/手动验证 |
| 输出模式 | 成功/失败 + 差异行提示 | 快速定位问题 |

### 工具接口

```bash
# 验证单文件
python scripts/verify-comment-only/verify_comment_only.py <原文件> <修改后文件>

# 验证目录（批量）
python scripts/verify-comment-only/verify_comment_only.py <原目录> <修改后目录>

# 输出示例（通过）
[OK] __init__.py — 代码等价，仅注释变更

# 输出示例（失败）
[FAIL] __init__.py — 代码不等价！原始 Hash: abc123, 修改后 Hash: def456
       差异行: 第 42 行原: "cells = []"  修改后: "cells = [1]"
```

## 词汇表设计

词汇表以 Markdown 表格形式存储于 `design-docs/glossary.md`，包含以下列：

| 列名 | 说明 |
|------|------|
| 英文术语 | 代码中使用的原始英文术语 |
| 中文译名 | 统一使用的中文术语 |
| 说明 | 简要解释，来源或背景 |
| 所在模块 | 主要出现的文件/模块 |

词汇表分类：

- **神经科学术语**：synapse（突触）、neuron（神经元）、connectome（连接组）等
- **NeuroML 建模术语**：Population（种群）、Projection（投射）、Instance（实例）等
- **电生理术语**：membrane potential（膜电位）、conductance（电导）、IaF（积分放电）等
- **线虫特有术语**：C. elegans（秀丽隐杆线虫）、gap junction（缝隙连接）等
- **c302 框架专有术语**：parameter set（参数层级）、data reader（数据读取器）等

## 注释规范（引用 python-code-style 技能）

按照项目 SP-CODE-2026-001 规范，注释须满足：

- 使用**中文**，关键词（`TODO`、`FIXME`、`:param:`）保持英文
- 行内注释：代码行末 `  # ` + 中文说明（`#` 前 2 个空格，后 1 个空格）
- 独立注释行：`# ` + 中文说明（顶格，对齐代码块缩进）
- 注释说明**为什么**，而非仅描述**是什么**
- 每段关键逻辑至少一条注释（条件分支、循环、异常处理、复杂表达式）

### 注释示例

```python
# 遍历所有连接，按突触类型分别创建 NeuroML 投射对象
for conn in connections:
    # 判断是否为电突触（缝隙连接），电突触使用 ElectricalProjection
    if conn.is_elec_conn():
        proj = ElectricalProjection(...)
    # 判断是否为分级（模拟）突触，用于 Level C+ 的持续电流建模
    elif conn.is_analog_conn():
        proj = ContinuousProjection(...)
    else:
        # 默认化学突触，使用事件驱动的 Projection
        proj = Projection(...)
```

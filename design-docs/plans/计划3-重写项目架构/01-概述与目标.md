# 01 - 概述与目标

## 背景

c302 是 OpenWorm 项目的子模块，用于生成秀丽隐杆线虫 302 个神经元的多尺度 NeuroML 2 网络模型。项目历时 8 年、550+ 次提交，功能稳定可用，但代码组织存在严重结构性问题：

1. **巨型核心模块**：`__init__.py` 承载 2,195 行、31 个函数、6 类不同职责
2. **扁平包结构**：`c302/` 根目录平铺 45 个 Python 文件（全树共 47 个 Python 文件、16,260 行），无子包划分
3. **无单元测试**：仅有 `test.sh` 集成测试，无 pytest 框架
4. **数据与代码混放**：XML/XLS 文件与 Python 源码同目录，参数硬编码为 Python 调用（5,901 行）
5. **代码重复**：USDR1/2 重复率 ~90%（~225/250 行），White_*.py 三文件模式相同
6. **工程化缺失**：隐式依赖未声明、命名不一致、传统 `setup.py` 打包

详见：
- 代码分析报告 `analysis-20260416-a855fcb`
- 重写架构设计报告 `refactor-20260417-b48af32`

本计划采用**自底向上重写**策略（而非渐进式重构），在 `project_r1/` 目录下从零构建新代码，保留功能等价性但不保留代码级兼容性。

## 目标

1. 在 `project_r1/` 目录下重写 c302 项目，产出功能等价的新代码
2. 按 6 个功能域（连接组数据读取、参数化系统、网络生成引擎、文件 I/O、仿真编排、配置脚本）+ 可视化层设计清晰的子包结构
3. 所有参数定义从 Python 硬编码迁移到 YAML 数据文件，支持继承和覆盖
4. 常量数据（302 神经元名称、96 肌肉名称）外置为数据文件
5. 建立完整 pytest 测试体系：行覆盖 ≥ 90%，分支覆盖 ≥ 80%
6. 所有代码从第一行起遵循 SP-CODE-2026-001 编码规范
7. 实现等价性验证：新代码对相同输入产生语义等价的 NeuroML 输出
8. 使用 `pyproject.toml` 替代 `setup.py` 进行包管理
9. 编写开发文档和使用文档

## 不做什么

- 不修改原代码 `project/c302/` 的任何内容（原代码仅作为参考和等价性验证基准）
- 不支持 owmeta 读取器（`OpenWormReader.py` 为可选依赖，第一版暂不实现）
- 不重写 `CompareMain.py`、`analyse.py`、`backers.py`、`NeuroMLUtilities.py`、`c302_info.py`（非核心功能）
- 不修改 303 个 `.cell.nml` 细胞形态文件、`LeakConductance.channel.nml` 共享通道文件和 23 个连接组数据文件的内容
- 不修改 7 个 XML 组件定义文件的内容
- 不重写 `data/GABA.py`、`NeuroML2/printNML2Info.py` 等子目录辅助脚本
- 不修改 GitHub Actions CI 工作流
- 不在本计划中处理 owmeta 可选依赖的集成

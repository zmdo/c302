# 01 - 概述与目标

## 背景

计划1（为 c302 源码添加中文注释）已于 2026-04-16 完成，44 个 Python 源文件全部添加了：

- SP-CODE 头块（功能描述 / 类与方法索引 / 更新日志 / 当前维护者）
- 中文 reST 格式 docstring
- 中文行内注释

但计划1 是"先覆盖再打磨"的策略——以全量覆盖为首要目标。在此过程中积累了以下待解决问题：

1. **遗留英文注释**：约 40+ 处分散的英文行内注释未被翻译（如 `# compute the required figure height`、`# dirty hack`）
2. **HACK/FIXME 标记**：4 处英文 HACK 注释需转为中文并标注清理方向
3. **注释覆盖不均**：核心复杂函数（如 `__init__.py` 的 `generate()` 函数，1867 行）部分逻辑块缺少行内注释
4. **`.py.md` 分析文档全空**：44 个源码分析文档仅有骨架，模块概要和分析记录均未填写
5. **缺少系统性审阅**：计划1 的验证仅确保"代码等价性"，未做注释质量审阅

## 目标

1. 对 44 个已注释的 Python 源文件进行逐文件审阅，发现并修正注释问题
2. 翻译所有遗留的英文行内注释为中文
3. 补充复杂逻辑块缺失的行内注释
4. 为每个源文件填写对应的 `.py.md` 分析文档（至少填写模块概要和分析记录）
5. 每阶段产出结构化勘误报告，存放于 `project/c302-docs/reports/`
6. 每阶段完成后提交并推送

## 不做什么

- 不修改任何可执行代码（与计划1 相同的硬性约束）
- 不重写 SP-CODE 头块结构（头块格式已标准化）
- 不修改 docstring 的格式（reST 格式已统一）
- 不修改 XML / LEMS / NeuroML 文件
- 不修改 `data/` 目录中的数据文件
- 不重构代码以"修正"注释中发现的代码问题（仅在分析记录中记录，不动代码）
- 不修改 `design-docs/glossary.md` 词汇表（词汇表已在计划1 中建立完善）

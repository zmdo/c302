# 03 - 方案设计

## 总体架构

```
勘误执行流程：

① 建立勘误框架
   审阅清单 + 评分标准 + 报告模板 + 扫描脚本
         │
         ▼
② 按层逐阶段审阅（阶段二 → 阶段七，共 6 个层级）
   每个阶段对该层所有文件执行：
   ┌─────────────────────────────────────────────────────────┐
   │  对每个源文件：                                          │
   │  (a) 逐行审阅 → 识别 A/B/C 类问题                       │
   │  (b) 修正问题 → 翻译英文注释、标注注释代码、补充注释       │
   │  (c) 填写 .py.md → 模块概要 + 分析记录                   │
   │  (d) 运行 verify_comment_only 验证代码等价性              │
   └─────────────────────────────────────────────────────────┘
         │
         ▼
③ 输出阶段报告
   project/c302-docs/reports/{YYYYMMDD}-勘误-{阶段名}/
   ─ 每阶段一个目录，含概览 + 逐文件发现
         │
         ▼
④ 提交并推送
   git add → git commit → git push（每阶段一次）
         │
         ▼
⑤ 收尾（阶段八）
   汇总全量勘误报告 + 验证 + 提交推送
```

## 四类问题的处理策略

### A 类：英文解释性注释 → 翻译为中文

直接将英文注释翻译为等义的中文注释。遵循 `design-docs/glossary.md` 词汇表。

```python
# 修改前
# Hack/guess
conn_number = 1

# 修改后
# 临时方案，连接数量使用猜测值
conn_number = 1
```

```python
# 修改前
# Write over network file written above...

# 修改后
# 覆盖前面生成的网络文件...
```

### B 类：注释掉的代码 → 分情况处理

| 子类 | 处理方式 | 示例 |
|------|---------|------|
| B1 — 调试遗留 | 在注释块前添加中文标注  `# [调试] 以下为保留的调试输出` | `# print(...)` 系列 |
| B2 — 备选方案 | 在注释块前添加中文标注  `# [备选] 以下为备选参数/配置` | `# params.set_bioparameter(...)` 系列 |
| B3 — 废弃代码 | 在注释块前添加中文标注  `# [废弃] 以下为旧版逻辑，已不再使用` | `# worksheet = workbook.sheet_by_name(...)` 系列 |

**注意**：不删除任何注释掉的代码（不做什么中已明确排除代码修改），仅在其前方添加中文标注行。

```python
# 修改前
# params.set_bioparameter("exc_syn_conductance", ".20 nS", "BlindGuess", "0.1")
# params.set_bioparameter("inh_syn_conductance", ".35 nS", "BlindGuess", "0.1")

# 修改后
# [备选] 以下为手动调试时替换的突触电导参数（来源: BlindGuess）
# params.set_bioparameter("exc_syn_conductance", ".20 nS", "BlindGuess", "0.1")
# params.set_bioparameter("inh_syn_conductance", ".35 nS", "BlindGuess", "0.1")
```

### C 类：注释覆盖不足 → 补充行内注释

对复杂逻辑块逐段补充中文行内注释，重点覆盖：

- 条件分支（`if`/`elif`/`else` 的判断意图）
- 循环体（迭代目标和终止条件）
- 异常处理（`try`/`except` 的预期异常）
- 复杂表达式（多步运算的中间含义）

### D 类：`.py.md` 分析文档 → 逐文件填写

每个文件勘误完成后，更新对应的 `.py.md` 文档：

1. **模块概要**：一段话描述模块职责和在项目四层架构中的位置
2. **分析记录**：以标准格式记录本次勘误发现

```markdown
### 2026-04-XX 注释勘误

**范围**：全文件
**发现**：
- A 类：X 处英文注释已翻译
- B 类：Y 处注释代码已标注
- C 类：Z 处补充了行内注释
**结论**：勘误完成，无需修改代码
```

3. **修改记忆**：添加一行记录本次修改

## 报告结构设计

### 目录命名

```
project/c302-docs/reports/{YYYYMMDD}-勘误-{层级名}/
```

示例：
```
project/c302-docs/reports/20260417-勘误-数据读取层/
project/c302-docs/reports/20260417-勘误-参数化层/
project/c302-docs/reports/20260418-勘误-网络生成层/
...
```

### 报告文件结构

每个阶段报告目录包含：

| 文件 | 内容 |
|------|------|
| `00-概览.md` | 本阶段涉及的文件列表、问题统计、处理结果汇总 |
| `{NN}-{文件名}.md` | 每个源文件的详细勘误记录（发现 + 修复 + 验证结果） |

### 单文件勘误报告模板

```markdown
# {文件名} 勘误报告

## 文件信息

| 项目 | 值 |
|------|---|
| 文件路径 | `project/c302/{文件名}` |
| 代码行数 | N |
| 层级 | {数据读取层/参数化层/...} |

## 发现汇总

| 类型 | 数量 | 行号 |
|------|------|------|
| A — 英文注释 | X | L123, L456 |
| B1 — 调试遗留 | X | ... |
| B2 — 备选方案 | X | ... |
| B3 — 废弃代码 | X | ... |
| C — 覆盖不足 | X | ... |

## 详细勘误

### A 类修正

| 行号 | 修改前 | 修改后 |
|------|-------|-------|
| L166 | `# Hack/guess` | `# 临时方案，连接数量使用猜测值` |

### B 类标注

（同上格式）

### C 类补充

（列出补充的注释及位置）

## 验证结果

- [ ] verify_comment_only.py 通过
```

## 审阅清单

每个文件审阅时依次检查：

| 序号 | 检查项 | 目标 |
|------|-------|------|
| 1 | SP-CODE 头块完整性 | 功能描述、类与方法索引、更新日志、维护者四项齐全 |
| 2 | 索引行号准确性 | 索引中行号与实际定义位置一致 |
| 3 | Docstring 完整性 | 所有 public 函数/类有中文 reST docstring |
| 4 | 英文注释残留 | 无 A 类英文解释性注释 |
| 5 | 注释代码标注 | 所有 B 类注释代码块前有中文标注行 |
| 6 | 行内注释覆盖 | 条件分支、循环、异常处理、复杂表达式均有注释 |
| 7 | 术语一致性 | 使用 glossary.md 中的标准译名 |
| 8 | 代码等价性验证 | verify_comment_only.py 通过 |

## 验证方案

复用计划1 的 `verify_comment_only.py` 验证工具：

```bash
# 验证单文件（需先备份原始版本）
python scripts/verify-comment-only/verify_comment_only.py <原文件> <修改后文件>
```

每个阶段开始前，从当前 git HEAD 提取该阶段文件的原始版本作为比对基线。

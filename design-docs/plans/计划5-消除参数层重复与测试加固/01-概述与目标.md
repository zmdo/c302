# 01 - 概述与目标

## 背景

计划 3 完成了 c302 的架构重写（`project_r1/`），计划 4 补全了全部 10 个参数层级并建立了 66 组等价性基线。评估报告（`comment-20260419-4f99cb7`）给出综合评级 **B+**，主要失分集中在可维护性维度（★★★☆☆），具体体现为：

1. **`factory.py` 是新的 God Object**：1,877 行、11 个类、72 个方法挤在单文件中，方法级重复率 58%（42/72）。`create_neuron_to_neuron_syn` 被定义 9 次，`get_exc_syn` / `get_inh_syn` 各 7 次——每次仅突触类和参数字段不同。
2. **继承结构异常**：`_HHC0Model` 直接继承 `_ModelBase` 而非 `_HHModel`，导致 `create_models`、`create_generic_*_cell`、`create_offsetcurrent_concentrationmodel` 四个方法被完整重写，与 `_HHModel` 的对应实现几乎逐字节相同。
3. **纯重复对**：`_HHC0Model` ↔ `_HHGradedModel`（`create_n_connection_synapse`、`is_analog_conn` 完全相同）；`_BC1Model` ↔ `_HHC1Model`（`get_exc_syn` / `get_inh_syn` 完全相同）。
4. **等价性测试 xfail 粒度过粗**：Muscles/Oscillator 的 xfail 标记施加于全部 11 个测试方法，但仅 `test_values_match` 实际失败，产生 162 个 xpassed 噪声。
5. **configs 自动发现缺失**：`_auto_import()` 硬编码 16 个模块名，新增配置需手工维护列表。
6. **factory 直接单元测试缺口大**：11 个工厂类中仅 D/D1/C0/C1 有直接测试，BC1/C/C2/W2D/A/B 无直接测试。

## 目标

1. **拆分 `factory.py`**：将 1,877 行单文件拆分为 `parameters/factory/` 子包（4-5 个文件），每个文件 ≤ 400 行
2. **消除方法级重复**：将可参数化的突触创建/查询方法提升至基类，通过类属性分派，消除约 600-800 行重复代码
3. **修正继承异常**：让 `_HHC0Model` 继承 `_HHModel`，消除 4 个完整方法的冗余重写
4. **细化 xfail 粒度**：仅对 `test_values_match` 在 Muscles/Oscillator 组合上标记 xfail，消除 xpassed 噪声
5. **实现 configs 自动发现**：`_auto_import()` 改为扫描 `configs/` 目录下的 `.py` 文件，删除硬编码列表
6. **补全 factory 单元测试**：为 BC1、C、C2、W2D、A、B 六个工厂类添加直接测试

## 约束条件

1. **等价性不能倒退**：重构后全部 66 组基线必须仍然通过，测试结果 ≥ `1285 passed, 36 xfailed`
2. **公共 API 不变**：`create_model(level)` 签名和返回类型不变，所有 config 脚本零修改
3. **基于新分支**：从当前 `refactor/f20160416` 创建 `refactor/f20260419` 分支，在新分支上工作

## 不做什么

1. **不重构 `generate()` 接口**：P1（引入 `GenerateConfig` 配置对象）范围较大，留给后续计划
2. **不引入参数名 enum**：P2（字符串匹配加固）需评估对已有 YAML 数据文件的影响，留给后续计划
3. **不新增仿真层集成测试**：P5（`@pytest.mark.integration`）依赖外部后端环境，不在本计划范围
4. **不修改 `model.py` 的 `is_level_*` 方法**：虽然基于 `startswith` 匹配，但当前工作正常且有测试覆盖
5. **不修改 config 脚本内部实现**：仅修改 configs 注册器的自动发现机制
6. **不修改 `generator/` 子包内部实现**
